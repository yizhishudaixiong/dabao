# Python打包工具（🐨 一只树袋熊出品）

> 把 Python 脚本一键打包成独立 EXE 的 Windows 桌面工具。
> 基于 Go + Wails + React 构建，底层调用 PyInstaller；亮色简约界面，分步向导，全程不需要命令行。

## 功能特性

### 环境：不用先折腾 Python

- **快速搜索**：自动查环境变量、Python 启动器、常见安装目录（含 conda）和你指定的根目录，**秒级返回，不扫盘**
- **深度扫描**：Python 装在任意角落（绿色版、非标准路径）也能找出来；每次都是实时扫描，装了 / 删了 / 移动了立刻反映
- 自动**过滤假环境**（Windows 应用商店别名、0 字节占位、沙箱运行时）
- 电脑上没有 Python？一键**下载内置便携版**（3.10 ~ 3.14 可选，国内代理加速 + 断点续传，装在工具自己的数据目录里，不碰系统），也可以**新建虚拟环境**

### 打包：一个向导搞定

- 程序名称、版本、作者、图标（`.ico` / `.png` / `.jpg` 自动转换）
- 单文件 / 多文件、显示 / 隐藏控制台、管理员权限运行
- 精简打包、排除用不到的重型库、手动补充隐藏导入、附加 PyInstaller 参数
- **UPX 压缩**：压缩器内置，勾选即用，无需联网下载

### 依赖：自动找、自动装

- 用与打包同源的 PyInstaller 分析引擎扫描依赖，**动态导入的模块也能发现**
- 缺失项一键安装到所选环境，支持官方源 / 清华源 / 阿里源 / 自定义镜像
- 打包时自动带上已装包的元数据，streamlit 等"导入时查询自身版本"的包不再报 `PackageNotFoundError`
- 打包完成后若产物里仍缺模块（PyInstaller 只把这写成警告、构建照样"成功"），日志末尾会直接列出缺了哪些、被哪个文件引用
- 失败时给出**中文原因 + 处理建议 + 最近输出原文**，不用自己啃英文报错

### 保护与资源

- **代码加密**：不加密 / 基础加密 / 深度加密（叠加 JIT 动态指令保护），只加密你自己写的模块，第三方库不动
- **资源一起打包**：勾选图片、配置、素材文件夹随程序进包；静态分析会提示代码里引用了哪些资源，**打包前还会再核对一次**——引用到、磁盘上有、但没勾进包的文件会直接列在构建日志里

### 使用体验

- 支持**拖拽**：`.py` 拖进窗口直接设为入口脚本，图片设为图标，文件夹加入打包资源
- **配置记忆**：可开启，下次打开自动还原全部设置
- 实时日志与进度、完成提示音；打包 / 安装依赖 / 下载都可随时取消
- 所有中间产物都在独立临时目录，结束后整体清理，**不会弄脏你的 Python 环境**

## 下载安装

前往 **Releases** 页面下载最新版本，两个平台同步发布：

- 码云（国内访问更快）：`gitee.com/yizhishudaixiong/dabao/releases`
- GitHub：`github.com/yizhishudaixiong/dabao/releases`

- 仅支持 **Windows 10 及以上**
- 需要 **WebView2 Runtime**（Win10 / Win11 一般自带；缺失时程序会弹原生提示引导安装）
- 绿色免安装，下载后双击即用

> 经 UPX 压缩或请求管理员权限的版本可能被部分杀毒软件误报，属常见现象。不放心可下载未压缩版本，或按 [开发文档](./DEVELOPMENT.md) 自行编译。

## 快速上手

1. 运行 `Python打包工具.exe`
2. **选择环境**：点「快速搜索」选一个 Python；没有就点「下载便携版 Python」
3. **程序信息**：填名称、版本、作者，选入口 `.py` 和图标，指定输出目录
4. **打包模式**：选单文件还是多文件，按需开启加密、UPX、资源打包
5. **依赖检查**：点「分析依赖」，缺失项一键安装
6. **开始构建**：点「开始打包」，等待完成，产物在你的输出目录里

## 分发前自查

打包成功不代表在别人电脑上一定能跑，建议先过一遍：

- 先在自己电脑上双击运行一遍，确认功能正常
- 对方报缺 `VCRUNTIME140.dll` 等 → 让对方装 **Microsoft Visual C++ 运行库**（2015-2022 x64）
- 被杀软拦截 → 让对方把程序加入信任；开了 UPX 的话，关闭后重新打包可降低误报率
- 单文件模式启动慢几秒属正常（启动时先解压到临时目录）
- 资源管理器里图标还是旧的 → 是系统图标缓存，把 exe 复制/改名到别处即可看到新图标

## 常见问题

**Q：搜不到我装的 Python？**
先用「快速搜索」（只查常见位置，很快）。装在 conda、绿色版目录或很深的自定义路径时，点「深度扫描」实时遍历全盘。仍找不到就手动选择 `python.exe`。

**Q：依赖页显示已全部安装，打包后却提示缺少模块？**
多半是动态导入（如按变量名 `importlib.import_module(...)`）或插件式加载。到「依赖检查」页的「隐式依赖导入」里手动加上模块名，然后重新打包。

**Q：开了「精简打包」后程序起不来？**
精简模式会排除 tkinter 等标准库。如果你的程序用到，请关闭精简后重打。

**Q：加密后程序启动变慢？**
深度加密叠加了 JIT 保护，启动会略慢；对防护要求不高时用「基础加密」即可。

**Q：打包到一半可以取消吗？**
可以，构建页和依赖安装都有取消 / 强制停止按钮。取消后临时文件会自动清理。

**Q：会改我的 Python 环境吗？**
不会。打包和依赖分析都在独立的临时工作区里进行，结束整体清理。往环境里装包只有两种情况：你主动点「安装缺失依赖」，或分析 / 加密时发现缺 PyInstaller、PyArmor 而自动补装（日志里会有提示）。

## 更新日志

### v6.3.0
- **修复单文件资源打包位置错误**：勾选的单个文件曾被放进「文件名/文件名」多一层目录，程序按 `sys._MEIPASS` 拼路径时打开的是个目录（`FileNotFoundError` / `PermissionError`）。文件夹资源不受影响
- **修复加密后子包模块丢失**：项目里有 `pkg/mod.py` 这类子包时，加密打包后产物会报 `ImportError: cannot import name 'mod'`。现在按包结构递归补齐所有本地模块
- **新增打包前后两道核对**：打包前列出「代码引用但没勾进包」的资源；打包后列出「产物里缺的模块」，都是构建成功但运行会崩的情况
- **依赖识别更准**：本地模块（`sys.path` 注入目录里的）不再被当成缺失的 pip 包；`try/except ImportError`、`if TYPE_CHECKING:` 里的可选导入不再报缺失；包名映射优先用环境里真实的发行版信息
- **资源识别更准**：支持 `Path(__file__).parent / "a.png"`、自定义封装（`QIcon`/`resource_path`）、字典与默认值里的路径；过滤 URL、glob、Qt 的 `:/icons/a.png` 与普通文案
- **修复装完依赖重新分析仍用旧结果**：分析缓存现在按「环境 + 项目源码」双指纹失效
- 其它：源码编码声明（GBK 项目）、超长命令行、Windows 保留文件名等边界问题

### v6.2.0
- 发布流程改为云端自动构建，码云与 GitHub 双平台同步发版（对使用者无功能变化）

### v6.1.0
- **修复 streamlit 等包打包后报错**：自动复制已装包的元数据（dist-info），不再报 `PackageNotFoundError`
- **修复依赖检查误报**：排除第三方库内部模块与相对导入，不再把库内部文件当成"缺失依赖"
- **修复资源依赖分析误报**：按 `pyvenv.cfg` 识别并跳过任意命名的虚拟环境，不再把库内部引用当资源
- **修复空结果崩溃**：列表为空时返回空数组而非 `null`，界面不再弹错误页
- **修复记忆功能**：启动还原完成前不重新扫描资源、不自动保存，重开不会"全选资源"或用空配置覆盖记忆
